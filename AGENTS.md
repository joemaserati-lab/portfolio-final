# AGENTS.md — Portfolio development contract

## Production sources
- `src/` is the only source of page structure, Astro routes, static metadata and templates.
- `public/` is the only source of client JavaScript, styles and media assets.
- Never create or edit duplicate assets, JavaScript, CSS or generated HTML at the repository root.
- `public/css/portfolio.bundle.css` is generated by `scripts/build-css.mjs` during `npm run build` and is not a source file.
- The source CSS load order is fixed in the bundling script. When editing CSS, preserve computed styles and breakpoint behaviour.

## Design
Read `DESIGN.md` first. Preserve monochrome #050505/#252525/#B9B9B9/#F5F5F5 with restrained #80FFCC accents.
Do not add generic gradients, glass panels, rounded cards or stock interfaces.
Project thumbnails stay grayscale, color is revealed on desktop hover/focus or a single mobile tap with 280 ms preview.
Never replace actual project covers with decorative placeholders; do not load a duplicate CSS background image for an existing project cover. Case-study media are pending real production assets; do not invent them.

## Implementation
- Preserve Astro, Three.js, CRT effects and the existing user interactions.
- Prefer focused edits to existing modules over new override-only files.
- Do not add new `!important` declarations to solve specificity conflicts.
- Keep keyboard navigation, reduced-motion support and pointer/touch parity.
- Keep browser History API routes and canonical URLs in sync.
- Do not add third-party packages or external assets without a demonstrated requirement.

## Before proposing a merge
1. Run `npm run build` and `npm run check`.
2. Validate narrow and short mobile layouts (320×568, 390×844, 667×375) and desktop (1440×900), including loader, project cover first tap, close/back, 3D head resume.
3. Review Lighthouse and Playwright logs: a successful build is not sufficient.
4. Preserve source-of-truth and check no legacy root files are reintroduced.
5. State any untested interactions, regressions or metrics instead of claiming perfection.
6. Work in feature branches and review diffs before merging to `main`.
