# AGENTS.md — Portfolio development contract

## Production sources
- `src/` is the only source of page structure, Astro routes, static metadata and templates.
- `public/` is the only source of client JavaScript, styles and media assets.
- Never create or edit duplicate assets, JavaScript, CSS or generated HTML at the repository root.
- `public/css/portfolio.bundle.css` is generated by `scripts/build-css.mjs` during `npm run build` and is not a source file. Production applies whitespace-only esbuild compression; CSS semantic transformations are intentionally disabled.
- The source CSS load order is fixed in the bundling script. The historical monolithic `style.css` is split, in unchanged selector order, across `foundation.css`, `workspace.css`, `visual-experience.css`, and `adaptive.css`, followed by existing stylesheet layers. Edit the relevant source module instead of rebuilding the monolith.
- When editing CSS, preserve computed styles and breakpoint behaviour. Do not reorder modules without visual and interaction regression checks.

## Design
Read `DESIGN.md` first. Preserve monochrome #050505/#252525/#B9B9B9/#F5F5F5 with restrained #80FFCC interactive accents and #FF2D3A exclusively for Doto glyphs (`.`, `•`, `[ ]`, `<>`). Keep both signals functionally distinct. The hero CTA and loader use square brackets, project cards use bullet plus year/status, CV places use brackets, and navigation labels stay white; the red Doto bullet appears only in the final horizontal desktop caption and active mobile label, never on transitioning desktop launchers. The doto-mono reading font is JetBrains Mono, except for the deliberately Doto-only Skills / Software & Tools taxonomy. Skills and Software & Tools both use red `[ ]` like Education, and every category keeps a single red `•`. Individual skill/tool items remain unmarked. The boot loader has no artificial minimum on any device, though desktop still waits for the first 3D head frame.
Do not add generic gradients, glass panels, rounded cards or stock interfaces.
Project thumbnails stay grayscale at rest. Desktop hover/focus reveals color; mobile uses the most visible card with a CRT scan transition and preserves single-tap project opening.
Never replace actual project covers with decorative placeholders; do not load a duplicate CSS background image for an existing project cover. Case-study media are pending real production assets; do not invent them.

## Implementation
- Preserve Astro, Three.js, CRT effects and the existing user interactions.
- Prefer focused edits to existing modules over new override-only files.
- Do not add new `!important` declarations to solve specificity conflicts.
- Keep keyboard navigation, reduced-motion support and pointer/touch parity.
- Keep browser History API routes and canonical URLs in sync.
- Do not add third-party packages or external assets without a demonstrated requirement.

## Before proposing a merge
1. Run `npm run build` and `npm run check` (GitHub Actions does this automatically for PRs).
2. For visual or copy changes, inspect the actual changed pages on desktop and mobile (e.g. 390×844 and 1440×900), without assuming compilation proves visual quality.
3. For changes to routing, navigation, loading, Three.js or other complex interactions, run the relevant Playwright or Lighthouse GitHub Actions workflow **manually**. The five expensive checks are never triggered by PRs, pushes or deployments.
4. Preserve source-of-truth and check no legacy root files are reintroduced.
5. State any untested interactions, regressions or metrics instead of claiming perfection.
6. Work in feature branches and review diffs before merging to `main`; get the user's approval for visible design changes.
